# AI 评测平台技术栈基线与开发规范

V1.0 · 2026-11-26 · 配套概要设计 V2.4、详细设计 V1.2、开发任务 V1.2

本文件补齐工程实施约束，与详细设计第 11 章共同构成开发基线。技术模块名称、数据所有权、接口编号和业务状态沿用现有设计；不新增产品模块或改变 B1—B4 范围。初期采用 Docker Compose。

**状态说明：技术选型与工程规则已在本次设计中明确；实际依赖锁文件、可运行业务镜像、企业环境联调和容量资格尚未交付。本文的命令与配置是待工程工作包实现的验收规范，不代表当前文档站点已具备平台后端。**

## 1. 基线范围与变更规则

| 对象 | 本次明确的规则 | 变更要求 |
| --- | --- | --- |
| 架构 | 模块化 Python 后端；控制进程与计算 Worker 分离；参考数据独立权限域 | 拆服务、换中间件、改变写入责任须 ADR 和受影响合同评审 |
| 部署 | Docker Compose；受信业务服务与不可信执行环境分离 | 不以本规范引入 Kubernetes、宿主机 Docker socket 或特权 Worker |
| 选型版本 | 表中版本线是解析约束；实际构建必须使用已验收的精确版本与镜像 digest | 不把版本范围写成生产镜像标签，不自动追随 latest |
| 业务规则 | 主 PRD、专项 PRD 与详细设计中的状态、用途授权、评分口径为依据 | 不以工具默认值替代需求；业务不明确登记澄清项 |
| 工程约束 | 编码、契约、迁移、测试、合并、发布规则在本文件统一 | 例外必须记录范围、风险、负责人、到期日与补偿验证 |

优先级：已确认需求约束 → 已批准架构决策 → 详细接口与数据库合同 → 本工程规范。发现矛盾须提交变更记录，不能由实现者静默选择。源码目录以本文件第 4 节及详细设计第 11 章为准，概要设计旧骨架路径按映射迁移。

| 身份 | 企业 OIDC；Authlib 1 兼容线 | JWT 验签固定 issuer/audience/算法白名单；项目授权在后端执行 | IdP 联调与撤权测试；权限管理 |
| 入口网关 | Nginx stable，精确镜像 digest | TLS、静态资源、API 代理、SSE；企业已有网关可替代此职责 | 网关配置与证书验收；平台工程 |
| 容器 | Docker Engine 受支持稳定版 + Compose v2 插件 | 固定宿主机安装版本；必须支持健康依赖、profiles、secrets | docker version / compose version 归档；平台工程 |
| 遥测 | OpenTelemetry SDK/Collector；Prometheus、Grafana | 优先复用企业采集与告警服务；无企业服务时采用 observability profile | 版本清单、关联链路与告警实测；运维监控 |
| Python 质量工具 | Ruff、mypy、pytest、pytest-asyncio、pytest-cov | 工具自身也锁定；mypy strict，Ruff 负责 lint 与 format | 开发依赖组及 CI 结果；后端 |
| 前端质量工具 | ESLint 9、typescript-eslint 8、Prettier 3、Vitest 4、Testing Library、Playwright 1 | Vitest 对应 Vite 兼容性验收；Playwright 版本与浏览器二进制同锁 | pnpm lock、组件及 E2E 结果；前端 / QA |
| 合同检查 | OpenAPI 3.1、JSON Schema 2020-12、openapi-typescript 7、oasdiff | 与既有合同版本核对后实施；不为换工具静默改写已有事件语义 | 合同摘要、生成器版本、破坏性差异报告；后端 |
| 安全检查 | Gitleaks、Trivy、pip-audit、pnpm audit | 扫凭据、源码依赖、最终镜像；扫描数据库时间必须记录 | 扫描报告与例外记录；安全 / 平台工程 |

**发布锁定的硬要求：**每个交付版本必须含精确的运行时补丁版本、工具版本、直接/传递依赖锁文件、基础与业务镜像 SHA256 digest、目标 CPU 架构、迁移版本、合同摘要、SBOM 和验证报告。缺任何必填值，发布检查失败；不得填 latest、main、TBD 或伪造 digest。版本表不能替代这份发布清单。

初次锁定：选择上述版本线中仍受维护且扫描通过的发行版本 → 解析依赖 → 完成第 10 节矩阵 → 固化 lock 与 digest → 记录 ADR。日常安装只用 `pnpm install --frozen-lockfile`、`uv sync --locked`；升级通过独立 PR，禁止在启动容器时执行 pip install -U / npm update。月度集中检查维护状态；停止维护或存在可利用漏洞时触发替代评审，不因表中版本线保留旧漏洞。

## 3. 评测框架与可选组件

| 组件 | 平台内位置与用途 | 隔离及版本要求 | 正式启用条件 |
| --- | --- | --- | --- |
| OpenCompass | 执行器的模型推理桥接；自动评分的 evaluator 桥接 | plugins/engines/opencompass；独立镜像 / lock / Python；按能力拆分推理与评分授权 | WP-37：固定仓库 commit/tag、数据与结果映射、取消/超时/重试、评分尺度验证 |
| AgentCompass | 执行器的 Agent 环境 / harness；自动评分的 benchmark 桥接 | plugins/engines/agentcompass；独立环境与受审工具集 | WP-38：先确认实际仓库和许可证，冻结 commit、环境初始化/重置及证据合同 |
| Ragas | 自动评分的 RAG 指标实现 | plugins/scorers/ragas；独立镜像；显式绑定 judge/embedding 模型 | WP-39：逐指标必需字段、NaN/缺失、分数范围与模型版本资格 |
| 本地模型 / GPU | 对象调用或特定框架 Worker 的推理后端 | 只在需要时启用；CUDA、驱动、PyTorch、推理后端形成独立组合 | GPU 资源、模型授权、显存/并发与复现验证通过 |
| 浏览器自动化 | 执行器 WebAdapter，Playwright | 浏览器 Worker 与普通 API Worker 分离，浏览器及镜像版本成对 | 浏览器版本、代理/证书、退出与工件回收验证 |
| 外部容器 / 可执行程序 | RemoteContainerAdapter / ExecutableAdapter | 受控远端环境或独立 VM；主平台无 Docker socket，无任意 shell 插值 | 包摘要、资源/网络白名单、销毁和越权测试通过 |

三类框架的依赖不得安装在 API/control 主镜像中；统一通过平台 ExecutionBundle / ScoringBundle 和固定结果合同交互。评分 Worker 可按授权取得参考投影，执行 Worker 不得取得答案或参考凭据。所有 Worker 均无平台主库、参考库或 RabbitMQ 凭据，领取工作和提交结果经既有内部网关。

OpenCompass 官方安装文档指出不同推理后端可能存在依赖冲突，部分代码评测还有特定 Python 限制。因此平台 Python 版本不强制覆盖所有框架；例外运行时必须纳入其独立资格矩阵。[OpenCompass 安装依据](https://opencompass.readthedocs.io/en/latest/get_started/installation.html)

B1 的 RAG 闭环仍按 WP-46 实现，不能因 Ragas 桥接工作包在 B3 而推迟 B1；可以先以平台已资格化的评分器实现同一指标合同。Redis、Elasticsearch、向量数据库、Kafka、Celery、Temporal 不列为 B1 必装依赖；只有已确认容量或功能缺口才通过 ADR 引入。

## 5. 后端编码与并发规范

1. Python 使用 snake_case 文件/函数、PascalCase 类、UPPER_SNAKE_CASE 常量。公共 Port、DTO、业务函数和返回值必须有类型；禁止无边界 Any、裸 except、捕获异常后返回成功。
2. 领域错误使用稳定错误码与类型，HTTP 层统一映射；响应不得泄露 SQL、凭据或完整内部堆栈。日志保留错误类别、trace_id 和安全的上下文。
3. Router 只做鉴权入口、参数转换和调用应用服务；业务校验、状态迁移、幂等和事务边界放 application；domain 维持纯业务规则。
4. 每请求 / 每后台处理单元独立 Session。禁止多个并发 asyncio task 共用 AsyncSession；后台任务不复用请求生命周期已结束的 Session。[SQLAlchemy 并发依据](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)
5. CPU 密集解析、压缩、推理进入 Worker；同步 S3 SDK 用有界线程池；大文件流式处理。禁止在 async 路由中 sleep、同步大文件读取或直接执行模型推理。
6. 所有外呼设置 connect/read/write/pool timeout 和总截止时间。默认只重试明确幂等的读调用；副作用调用依赖动作账本与业务幂等合同。超时不等于对方未执行，不直接重做外部动作。
7. 资源池有上限；取消须释放连接、临时文件与租约。服务退出先停止领取新工作，再完成或移交已有工作；不得把 SIGTERM 当作任务成功。
8. 时间持久化用 UTC、带时区时间戳；耗时使用单调时钟。计费金额使用 Decimal 与明确币种/精度，不用浮点累计；单位、空值、INCONCLUSIVE 原因码按合同处理。

Ruff：行宽 100、Python 3.12、E4/E7/E9/F/I/B/UP/ASYNC 规则，format 与 lint 分别检查。mypy strict 覆盖业务包和入口；第三方无类型依赖只能在适配器边界局部隔离并注明原因，不允许全局 ignore_missing_imports。配置片段见第 13 节。

## 6. 前端开发规范

1. TypeScript 开启 strict、noUncheckedIndexedAccess、exactOptionalPropertyTypes；组件 props 不使用 any。OpenAPI 生成类型不可手改；业务映射写在独立 adapter 函数。
2. TanStack Query 管服务器状态，antd Form 管编辑态，本地 state 管 UI 临时状态。查询 key 必须含项目与资源标识；切换项目、退出登录、权限变更时撤销请求并清理相关缓存。
3. 正式任务状态、评分采用、报告结论与成本事实以服务端为准。SSE 只触发查询或展示已确认投影；断线补查权威状态，不能凭客户端事件计数推算成功。
4. 所有页面覆盖 loading / empty / forbidden / error / stale / success；错误展示可追踪 request_id。保存操作显示状态，重复点击不产生新业务事实；权限按钮隐藏不能替代服务端授权。
5. 只显示必填字段，可选项折叠；核心编辑区居中，保持既有编号与术语。键盘操作、焦点、字段 label、错误关联必须可用；颜色不能作为唯一状态提示。
6. 大列表服务端分页；导入提供预校验和错误行定位；图表按需加载。富文本经过白名单净化，默认禁用危险 HTML；不得把 Token、参考答案或敏感数据集放 localStorage。
7. Session 采用企业身份方案确定的安全凭据载体；若使用 cookie，设置 HttpOnly/Secure/SameSite 并实施 CSRF 防护；跨域仅允许明确 origin，不使用带凭据的通配配置。

ESLint 同时启用 TypeScript、React Hooks、promise 安全检查；Prettier 统一格式。组件测试观察用户可见行为；不以快照或 mock 调用次数代替保存、冲突、越权和恢复验证。

## 7. 接口、事件与数据库规范

| 范围 | 必须遵守 | 合并检查 |
| --- | --- | --- |
| 接口目录 | 每个新增或修改接口登记 operationId、提供模块、直接调用模块、同步/异步、权限、输入输出、错误、幂等、超时、限流与来源 CT | 同步更新详细设计逐接口清单；无 owner/调用者的接口不进入正式集成 |
| 合同同源 | contracts/http 为对外批准合同；FastAPI 导出与批准合同比对；生成 DTO 不能倒过来掩盖合同变化 | Schema 校验、生成后 git diff 必须为空；破坏性变更须新版本与迁移计划 |
| 兼容性 | 新增必填字段、删字段、收窄枚举、改变单位/权限/错误语义均需评审；扩展枚举也检查旧客户端穷举处理 | 提供方与全部直接依赖方签认；不只看路径是否变化 |
| HTTP 语义 | 方法/路径/成功响应沿用 op001—op108；错误体沿用既有合同；403/404 避免泄露跨项目资源，409 标识并发或幂等冲突 | 黄金样例、负向样例、跨项目、同键重放和版本冲突测试 |
| 异步任务 | 长任务返回既有 operation/work 引用并提供查询；不通过扩大 HTTP timeout 代替异步设计 | 请求断开仍可查询；取消与完成竞争符合状态机 |
| 消息 | 保留既有事件 Envelope；event_id、类型/版本、聚合键、追踪信息及业务数据按 Schema 校验 | Inbox 去重；同事务写领域事实与 Outbox；发布 confirm 后标记；消费落库后 ack |
| 重投 / DLQ | 有界重试、指数退避与抖动；错误分类；毒消息进入死信并可审计重放 | 重放保留原事件 ID/因果链；禁止无限立即 requeue；告警可定位受影响任务 |
| 数据责任 | 表由既有模块拥有；跨模块写入通过应用服务/UoW；Worker 不写平台表 | 事务失败领域记录与 outbox 一起回滚；权限角色最小化 |
| 并发 / 约束 | 唯一、外键、CHECK 与必需 NOT NULL 保留；查询含项目隔离条件；状态更新 CAS 或锁 | 实际 PostgreSQL 并发测试，禁止用 SQLite 替代 PG/RLS 验证 |
| 查询 | 列表分页、有序游标或明确 offset 规则；关键访问路径建索引；禁止 N+1 | 代表数据量 EXPLAIN、查询数与耗时记录；不预设未经实测的容量结论 |

RabbitMQ 确认只代表消息接收层面的结果，不代表业务已完成。生产需 durable 队列、persistent 消息、publisher confirm 与不可路由消息处理、manual ack；具体队列型别与企业 broker 策略一起冻结。单节点部署的持久化与备份不等于多副本容错。[RabbitMQ 确认依据](https://www.rabbitmq.com/docs/confirms)

迁移采用 expand → backfill → validate → 切换读取 → 兼容窗口结束后 contract。每次迁移给出锁影响、预计扫描量、超时、回滚边界与备份点；大回填可分批、可续跑。发布只允许一个迁移执行者；应用启动不得并发自动迁移。验证空库安装、上一发布升级、旧应用兼容新结构、失败恢复；数据破坏性迁移不以 downgrade 脚本冒充可恢复方案。

## 10. 测试策略与 CI 合并门槛

| CI 检查 | 触发范围 | 阻断条件 / 必交付证据 |
| --- | --- | --- |
| static | 每个代码 PR | Ruff lint/format、mypy strict、ESLint、Prettier、tsc 全通过；无新增违规导入 |
| contracts | HTTP / DTO / 事件 / 调用方变化 | Schema 合法、生成文件无漂移、破坏性差异得到迁移处理；逐接口清单完整 |
| unit | 受影响业务与前端组件 | 状态机、权限、评分归一化、预算/金额、取消竞争等确定性测试通过；不以 mock 调用断言替代业务结果 |
| integration | 后端、迁移、MQ、存储、身份变化 | 真实 PG/MQ/S3 合同；事务、幂等、重复/乱序、RLS 与越权通过；数据库不使用 SQLite 替代 |
| migration | DDL / ORM / Alembic 变化 | 空库安装、N-1 升级、兼容与故障恢复通过，记录耗时/锁等待和数据校验 |
| build | 代码 / 依赖 / Dockerfile 变化 | 前端生产构建、业务镜像构建、Compose config 校验、镜像无未锁定依赖；生产不引用源码 bind mount |

| e2e-smoke | 关键流程、UI、合同及发布候选 | 自动/人工/混合评分路径、统一台账、保存恢复、取消、报告与项目隔离通过；报告保留失败截图/trace |
| recovery | 租约/编排/完成/存储变化；每个发布候选 | 提交前后崩溃、worker 死亡、MQ 重投、S3 暂断、迟到完成、备份恢复验证；状态无错误成功 |
| qualification | 对象 / 引擎 / 模型 / 映射版本变化 | 逐能力黄金集与负向集；数据行对齐、单位/尺度、参考隔离、超时和用量；结论绑定精确版本 |

合并要求：适用检查全通过，关键安全/事务不变量场景必须全部覆盖；新增或修改业务代码的分支覆盖率目标不低于 80%，总体覆盖不得倒退。覆盖率是补充指标，不能抵消缺失的并发或授权场景。生成代码不计入分母但必须检查生成一致性。

文档纯变更运行链接/格式/示例语法检查，不强行启动无关 GPU 测试。CI 根据受影响路径选择任务，但必须有一个总门禁检查判断“应运行的检查确实成功”，不能把被意外跳过当作通过。失败日志、JUnit、覆盖率、合同差异与测试数据版本归档，工件权限与留存期按第 14 节确认。

不稳定用例不得靠无限重试刷绿。基础设施偶发重试必须保留首次失败；关键授权、冻结、评分采用、重复完成用例不能隔离后仍批准发布。LLM 质量评估使用固定样本/评分口径和允许波动范围；确定性 CI 使用录制或 stub，真实模型资格单列。

## 11. Git、评审与完成定义

采用 main 主干与短生命周期 feat/fix/docs 分支，分支关联工作包/需求。提交格式 `type(scope): 具体行为`，scope 沿用技术模块名。禁止在 main 强推；合并前至少一名非作者评审。跨模块合同需要提供方与直接调用方评审，数据库迁移与权限变更需对应负责人参与。

PR 必须说明：需求/工作包 → 行为变化 → 受影响模块/接口/表 → 兼容与迁移 → 验证证据 → 发布与恢复条件。AI 辅助生成代码遵循同样门槛，由提交者负责理解、验证与许可证核查；不得以“生成工具已检查”替代验证。

工作包完成必须同时满足：实现与批准合同一致；适用 CI 全绿；评审问题关闭；接口清单/字段字典/迁移/运行说明同步；无未解释的 TODO/TBD 假实现；示例能复现；故障分支验证；交付物可追溯到 commit 与锁定版本。产品验收和技术完成分别记录，不以文档已写或页面可展示替代业务可用。

## 12. Docker Compose 构建、发布与恢复

| 阶段 | 必须执行 | 失败处理 |
| --- | --- | --- |
| 构建 | 在受控 CI 构建一次；固定依赖、基础镜像 digest；非 root、最小运行层、SBOM 与扫描 | 任何未锁定依赖、密钥残留、关键扫描问题阻断 |
| 测试环境 | 同一镜像 digest 部署；执行迁移与最小闭环；验证网络、证书、服务身份与参考隔离 | 修复后重新产生发布候选，不在服务器临时修改包 |
| 发布前 | 核对配置摘要/镜像/迁移/合同、备份可恢复、容量空间、任务排空策略与恢复条件 | 缺恢复证据不执行结构性迁移 |
| 发布 | 暂停新领取；等待受影响工作完成或按协议移交；单一迁移任务；按依赖启动并检查 ready | 不依靠 Compose start 顺序认定数据库已就绪；有界重试与健康依赖 |
| 验证 | 查询旧任务、发起新闭环、检查证据和评分采用、确认异常队列与日志 | 错误越权、重复外部动作、结果损坏、迁移失败立即中止并按预案恢复 |
| 回退 | 兼容结构下回到上一镜像/配置；不兼容数据变化执行经演练的恢复或前向修复 | 不自动执行破坏性 down migration；保留故障证据和恢复记录 |

只有入口网关暴露业务端口；DB/MQ/内部网关/参考服务不暴露公网。生产服务启用资源限制、日志轮转、只读根文件系统（必要写目录单列）、drop capabilities 和 no-new-privileges；不挂 Docker socket。迁移任务与业务运行账号分离。

发布清单必须记录 app_version、git_commit、每镜像 digest、runtime/toolchain 精确版本、依赖锁摘要、contract_hash、migration_revision、config_hash（不含 secret）、目标架构、测试报告引用、备份点、前版本和恢复方案。测试与生产提升同一镜像；不在生产 rebuild。

Compose 健康依赖解决启动阶段就绪检查，不提供运行期间自动依赖恢复或跨机 HA。单节点方案接受停机发布窗口；窗口、RPO/RTO、保留期限与阈值由部署条件确认后冻结，不能把文档中的建议值写成已达成 SLO。[Compose 启动依据](https://docs.docker.com/compose/how-tos/startup-order/)
